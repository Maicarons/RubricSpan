## 一、为什么是"阅微"

"阅微"二字，取自"见微知著"。主观题阅卷，本就是一件见微知著的事：

一个得分点，藏在学生弯弯绕绕的表述里；一分之差，可能落在"戊戌变法"与
"百日维新"这对同义异名之间；而最难的，是判断学生**是真的懂了**，
还是仅仅从题干里抄了一句漂亮话。

机器阅卷不难，难的是**像老师一样阅卷**：

- **可解释** —— 给出分数的同时，标注命中每个得分点的原文片段，教师可逐条复核；
- **可同义** —— "戊戌变法 / 百日维新 / 维新运动"，在阅微眼里是同一个答案；
- **可抵赖** —— 题干剥离 + 从严阈值，把"忠于题干"的伪证据拦在门外；
- **可本地** —— 全链路 Rust 推理，单二进制，无 Python、无云端依赖，
  普通 PC 与本地 GPU 即可运行；OCR 识别、评分、审阅闭环全部离线完成。

## 二、1.0-flash：一份答卷

M0 到 M8，八个里程碑，从数据清洗到打标，从训练到 Rust 化推理，从 OCR 恢复到
性能调优——1.0-flash 交出的答卷是：

| 指标 | 数值 |
|---|---|
| 系统级 ScoreCorr（Pearson） | **0.9654** |
| 逐点准确率（36 卷同批对照） | **0.8402**（改进前 0.7160） |
| MAE | **1.569**（改进前 2.667） |
| 零分卷被给分率 | **18.0%**（改进前 63.6%） |
| 等价给分率 | 0.9554 |
| 推理延迟 | GPU 单题约 50–150 ms，会话池并发吞吐 35 题/秒级 |

> 数字背后是一次次"较真"：34 条高置信分歧逐条仲裁、题干污染的系统性修复、
> 出厂阈值从严再从严——因为**给错一分，就是辜负一次努力**。

- 模型厂库：`RubricSpan-mrc-1.0-flash` · `RubricSpan-similarity-1.0-flash`
  （Hugging Face：[Maicarons](https://huggingface.co/Maicarons) · ModelScope：[Mai2026](https://www.modelscope.cn/models/Mai2026)）
- 代码仓库：[github.com/Maicarons/RubricSpan](https://github.com/Maicarons/RubricSpan)（AGPL-3.0）
- 模型许可：CC BY-NC-SA 4.0（训练数据含非商业来源，商业使用需另行取得数据授权）

## 三、1.0-pro：下一堂课

flash 是基线，pro 是野心。

我们为 1.0-pro 准备了**全部八路新数据**：历年高考真题（2010–2022，含主观题参考答案）、
中学语文阅读理解、古诗文默写题库、以及 CMMLU / C-Eval 等中学文科知识基准——
归一化 **68,349 条**，相似度训练对 **168,121** 对，MRC 负例 **27,806** 条。

旧数据打底，新数据淬火。1.0-pro 将把"同义识别"与"拒判沾边"练得更稳，
目标是在 36 卷同批 e2e 上再进一步：零分带给分率压到 **10% 以下**。

训练方案已就绪（[train-1.0-pro](/reports/train-1.0-pro)），**即将开训**。

## 四、致教师

有人说，技术最终会取代教师。我们更愿意相信：

> 技术负责"看见"每一份答卷，教师负责"看见"每一个学生。

阅微能做的，是把批改红笔的时间还一点给备课，把统计分数的夜晚还一点给谈心，
把"这道题为什么扣分"讲得明明白白——让老师把省下的力气，花在更值得的地方。

今天，祝每一位老师，教师节快乐。

愿红笔有温，愿匠心不负。
