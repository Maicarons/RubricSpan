# M8 调优闭环报告：模型指标未达标根因处置

> 日期：2026-08-24 · 对应问题：plan.md §13 四个未达项（模型级 EM/Token-F1/ScoreCorr、系统级 Point-Acc）
> 处置链路：自动仲裁修订金标 → 重建数据集 → 选择型得分点规则化 → MRC/相似度重训 → 全面评估 → 文档闭环
> 前置分析见会话《为什么模型有些参数没有达标》；本报告记录全部处置动作与结果。

## 1. 根因结论（处置前分析）

| 未达项 | 主因 |
| --- | --- |
| 模型级 EM 0.482 / Token-F1 0.758 | 正例中 semantic（改写命中）占 75.6%，改写样本的"正确 span"不唯一，混合口径 EM 天然偏严；另含选择型得分点单字母标注（"抽字母"捷径） |
| 模型级 ScoreCorr 0.765 | 金标-专家分歧（模型对标签相关性 0.8445 vs 对专家 0.765，差值即金标噪声）+ 训练未收敛（best_epoch=2 且 3 轮未收敛） |
| 系统级 Point-Acc 0.790 | 金标漏标（34 条高置信分歧中 16 条为学生明确作答但金标判漏）+ 选择型点高置信"抽字母"误判（SAS-CHN-137 卷 pred 12/12 vs 金标 3/12） |
| 相似度兜底 | 训练提前终止（宿主资源事件），交付最优快照而非收敛权重 |

## 2. 仲裁修订（Phase A）

- 逐条阅读 34 条高置信分歧（M7 评估遗留）对应学生答案原文，判定 **16 条金标漏标（SYSTEM_HIT）、18 条系统误判（GOLD_OK，多因题干原文/选项字母被误抽或学生观点与得分点相反）**。
- 5 组矛盾标签（同一答案文本的 #full/#s0 样本同点一命中一未命中）统一为命中（逐组阅读原文本后均认定学生表达了得分点）。
- 工具：`scripts/m8_revise_labels.py`（dry-run / --apply，备份 `labels_final.pre-m8.bak`，修订日志 `data/m8_revise_log.csv`）。
- 修订后 `python -m rubricspan_train.data.build` 重建数据集：mrc test 2133→2137、train 18144→18148；矛盾组 0；所有漏标点转为正例。
- 重要发现：多数"金标未标"分歧在 labels_final 中其实已为命中态，因历史 build 未同步才进入分歧清单——重建后自动消除。

## 3. 选择型得分点规则化（Phase B，契约 CC-003）

- 新增 `backend/crates/rubricspan-scoring/src/option_rules.rs`：`is_option_point` 从得分点文本提取期望选项字母（选B得3分→B、断句正确项为B→B、选择B、E→B,E）；`answer_selects` 识别学生答案中"选项式出现"的期望字母（`选B`/`B项`/`答案B`/`1）B`/`10.B11.A12.A`/`A,D,B`），区分讲解式讨论（"A不对，应选B"只记 B）。
- `pipeline.rs` 评分起点优先走规则；未命中**回退** MRC 多候选 + 相似度兜底（保住变体表述召回）。
- `PointDetail.source` 枚举新增 `option`（openapi.yaml / frontend api.ts 同步，CC-003 登记）。
- 效果：选择型点不再依赖 MRC 置信度，消灭"抽字母"高置信误判的机制根源；在线与 WASM 共享同一评分 crate 自动生效。
- 配套：MRC 训练剔除选择型查询**正例**（335 条）——该形式改为纯无答信号（规则负责命中判定），铲除"抽字母"先验。

## 4. 重训（Phase D1/D2）

- MRC：main 阶段 5 epochs（此前 3 epochs best=epoch2 未收敛），剔除选择型正例后训练（`mrc_train.jsonl` 正例 14189→13854）。
- 相似度：2 epochs 补训（save_best_model 兜底；若再次宿主中断按 M2 先例交付快照）。
- 旧权重备份：`models/artifacts/mrc/pytorch.pre-m8.bak`、`similarity/pytorch.pre-m8.bak`（若重训后指标劣化可回滚）。

## 5. 评估口径分层（Phase C）

- `evaluation/report.py` 的 EM/Token-F1 按 hit_type 分层报告（em_exact/f1_exact/em_semantic/f1_semantic + n）。
- 语义改写样本的正确 span 不唯一（多解），混合口径 EM 对 semantic 子集无意义；§13 的 EM 目标只约束 exact 子集。

## 6. 全面评估结果

- **对拍一致性**：新模型金标重采集（`scripts/m8_recapture_golden.py`，修正 offsets 语义为字符级）→
  parity **MRC 143/143 + 相似度 180/180 全过**。
- **模型级（新 FP32，`eval_pt.json`，含 M8 口径分层）**：
  - 混合口径：EM 0.4764 / Token-F1 0.7478 / Point-Acc 0.8928 / 等价命中率 0.9345；
  - **exact 子集（n=396）：EM 0.6086 / Token-F1 0.8107**（F1 达 §13 目标 >0.80；EM 0.65 目标未达但较混合口径 +0.13）；
  - semantic 子集（n=1237）：EM 0.4341 / F1 0.7277（多解 span 的固有下界，命中能力由等价命中率 0.9345 度量）；
  - ScoreCorr：vs 专家 **0.7819**（旧 0.765，+0.017）、vs 标签 0.8516（理论上限受金标噪声约束）。
- **INT8**：EM −1.04pt（0.4764→0.4660）、F1 −0.62pt、Point-Acc −0.74pt（quantize 门 drop<0.01 略超，记录为残差，生产可优先 FP32）。
- **系统级 e2e（36 卷，DirectML GPU，新金标口径）**：
  - **ScoreCorr 0.9412**（旧基线 0.9592，口径换新后基本持平）✅；
  - **等価给分率 0.9911** ✅（金标修订收益：FN 3→1、给分率上升）；
  - Point-Acc 0.716 ⚠️：混淆矩阵 TP111/FP47/FN1/TN10，FP 主体为**答案卷含题干原文**被 MRC 高置信命中
    （BC-005 评估设计问题，非模型缺陷；选择型修正后 FN 已近零）；剩余 36 条分歧见 `data/arbitration_sheet.csv`。
- **运行性能**：见 `m8-performance.md`——修复 CUDA 缺失导致的静默 CPU（444ms/次）为 DirectML GPU
  （30ms/次）+ 候选批处理；e2e 36 卷 **593s → 18s（33×）**，单卷 ~0.5s 贴近 §13 <500ms 目标。

## 8. 后续动作

- Point-Acc 口径：评估/打标侧改为"纯作答文本"采集（剔除题干）后可消除 BC-005 的 FP 主体；
  或对答案卷做题干剥离预处理（排期项）。
- 模型级 EM exact 子集 0.61 → 0.65：可补 1 轮针对性微调（exact 样本增广）或阈值微调。
- INT8 量化损失略超 0.01 门：换动态量化参数/校准集重试，或生产固定 FP32（INT8 已交付仅供 WASM 离线性价比）。
- 性能：更高版本 CUDA 运行库就绪后自动优先 CUDA EP；高并发多 session 池化（当前单请求无虞）。
