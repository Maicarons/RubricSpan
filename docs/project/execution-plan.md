## 1. 计划概述

### 1.1 项目目标（摘自技术方案，作为验收主线）

构建一套完整的本地化主观题阅卷系统，验收时须同时满足以下七项：

1. **可解释评分**：给出分数的同时标注学生答案中命中每个得分点的原文片段；
2. **本地可运行**：推理在本地 GPU / 普通 PC 完成，评分链路不依赖在线大模型；
3. **工程可交付**：前端、后端（Rust 在线 + WASM 离线两套）、训练流水线、试卷文本识别四大部分齐备；
4. **数据自供给**：无人工标注条件下，用大模型（OpenAI 兼容接口）自动生成训练标签；
5. **纸质试卷可接入**：试卷扫描件/照片经 RapidOCR 自动识别为中文文本后进入评分流程；
6. **同义答案可识别**：等价表述扩展 + 语义相似度兜底，正确处理"戊戌变法/百日维新/维新运动"类答案；
7. **标准答案自然语言输入**：教师粘贴自然语言标准答案，系统自动解析为结构化评分配置。

> 达成情况（2026-08-24）：① ✅　② ✅　③ ✅　④ ✅　⑤ △（OCR 已暂停，`/api/ocr` 返回 501）　⑥ ✅　⑦ ✅。

### 1.2 范围界定

**范围内（本计划覆盖）：**

| 工作流 | 内容 |
|---|---|
| 数据与打标 | 数据集获取、合成答卷生成、大模型打标流水线、对齐后处理 |
| 模型训练 | MRC 抽取模型（mengzi-bert-base）训练、相似度模型（text2vec-base-chinese）微调、ONNX 导出与量化 |
| OCR 集成 | RapidOCR 本地推理、作答区定位、`/api/ocr` 服务化（实际：M3 贯通，M8 随去 Python 化暂停） |
| 后端 · 在线 | Rust（Axum）HTTP 服务、GPU 推理引擎、评分调度、SQLite 持久化、标准答案解析接口 |
| 后端 · 离线 | 轻量模型 WASM 化、浏览器端单题离线评分演示 |
| 前端 | Next.js 15 阅卷工作台、标准答案录入/解析预览、OCR 预览、批量阅卷与导出、在线/离线切换 |
| 联调与评估 | 全链路联调、指标评估、量化优化、打包交付 |

**范围外（明确不做，避免范围蔓延）：**

- 原生移动端应用；
- 多租户/账号权限体系（单用户本地使用为基线）；
- 客观题（选择/填空自动判分）；
- 手写体识别模型的自训练（使用 RapidOCR 现成模型 + 置信度过滤 + 人工核对兜底）；
- 分布式多机部署。

### 1.3 总体策略

- **契约先行**：OpenAPI 接口契约、评分配置 JSON Schema、模型产物目录规范在第 1–2 周冻结，前后端与训练侧并行开发；
- **纵向切片验证**：每个阶段结束前跑通一条"最小端到端链路"（哪怕用假数据），避免最后一周才集成；
- **双后端共模型**：Rust 在线与 WASM 离线共用同一套 ONNX 模型文件与评分配置，保证两端评分结果一致；
- **评估贯穿**：评估脚本在打标阶段就建立，每个模型迭代都能一键复算指标。

## 6. 仓库结构与配置管理

### 6.1 建议仓库结构（Monorepo）

```
RubricSpan/
├── data/                  # raw（原始数据集）/ synthetic（合成答卷）/ processed（训练数据）
├── contracts/             # 冻结契约（OpenAPI、JSON Schema、产物规范）

├── models/                # 导出模型产物（.gitignore 管理，大文件走本地/附件分发）
└── docs/                  # 项目计划、契约变更记录、评估报告、bad case、部署手册
```

### 6.2 分支与版本策略

- `main`：始终可构建，里程碑评审通过后合并；

- 每个里程碑打 tag：`m0-env`、`m1-labeling`、…、`m7-release`；
- 模型产物与大数据文件不入库，用 `models/README.md` 记录获取方式与校验值（哈希）；
- 提交信息说明"改了什么 + 为什么"，契约相关变更引用变更记录编号。

## 7. 质量保障与验收方案

### 7.1 测试策略（分层）

| 层级 | 范围 | 时机 |
|---|---|---|
| 单元测试 | 对齐后处理、评分逻辑（多候选抽取/阈值分支/加权汇总）、Schema 校验 | 随开发，合并前必须通过 |
| 契约测试 | 后端接口对 `openapi.yaml` 的符合性 | M4 起，CI 自动化 |
| 一致性测试 | PyTorch↔ONNX 输出、在线↔离线评分结果 | M2-6、M6-4 两个节点 |
| 端到端测试 | 四条链路（文本阅卷/图片阅卷/同义答案/标准答案解析）固定用例 | M5 起，M7 全量回归 |
| 评估测试 | §13 指标体系一键复算 | M2 起，每次模型迭代必跑 |

### 7.2 最终验收指标（引自技术方案 §13，含实测）

| 指标 | 目标值 | 验证方式 | 实测（2026-08-24） |
|---|---|---|---|
| Exact Match | > 65% | 固定测试集一键评估 | 模型级 48.2% ⚠️ 裁剪至迭代闭环 |
| Token-level F1 | > 80% | 同上 | 75.8% ⚠️ 同上 |
| Point-wise Accuracy | > 85% | 同上 | 模型级 89.4% ✅；系统级 79.0% ⚠️ 仲裁闭环中 |
| Score Correlation（Pearson） | > 0.85 | 与专家给分对照 | **系统级 0.959 ✅**（模型级 0.765 裁剪） |
| Human Agreement（Cohen's Kappa） | > 0.7 | 人工阅卷对照子集 | 未实施（裁剪） |
| 等价命中率 | > 80% | 同义专项测试子集 | 模型级 94.3% ✅ / 系统级 97.4% ✅ |
| 单题推理延迟（GPU） | < 500ms | 压测报告 | M8 重构后待回归复测 |
| OCR 字符级准确率 | 印刷体 > 95% / 手写体 > 85% | 样张集分体统计 | 随 OCR 暂停搁置 |

> **核心指标 Score Correlation 已以系统级 0.959 达标**；未达项均有明确处置路径（bad case 登记 / 34 条仲裁清单 / 迭代闭环），详见 M7 评估报告。

### 7.3 数据质量门

- 打标对齐成功率 > 90%（M1 出口）；
- 抽检标签可接受率 ≥ 90%（M1 出口）;
- semantic 样本占比 ≥ 15%（M1 出口）。

### 7.4 迭代闭环（上线后）

按技术方案 §16：收集 bad case（含 OCR 误识别、同义漏判）→ 大模型重新打标 → 增量微调 → 回归评估 → 发版。`docs/quality/bad-cases.md` 为唯一登记入口。
