## 运行与成本记录（供 M2 预算参考）

- **多端点 fallback**：`.env` 配置 7 端点队列（免费端点为主 + 付费端点兜底），
  每次调用从队首开始，整轮重试耗尽自动切换（`labeling/client.py`）。
- **实际消耗**：全程约 30M tokens（打标为主）。免费端点存在日额度（某免费端点中途 429 耗尽，
  由后续端点承接）；个别免费端点拒绝 temperature>1.0，自一致性投票温度定为
  0.5/0.9。
- **断点续跑**：全程三次中断重启（成本管控、并发调参），增量落盘设计保证零重复消费。
- 残余缺口：7 个样本打标失败 + 121 个样本所属题解析失败（可忽略；如需可重跑
  `parse-points --with-reserve && label --with-reserve && selfcheck && quality && build`）。

## 关键决策

1. **student_answer 回填**：模型只输出 question_id + point_labels，原文由流水线回填后再过
   `labeling-schema.json`，保证对齐基准与原文一致（实现细节，非契约变更）。
2. **fragment/synthetic 全量入池**：MRC 负样本天然充足（miss 点 12522），按 22% 目标
   分层抽样；synthetic 主导正样本（12141），真实答卷（full+fragment 10448）保证分布。
3. **混合模型打标**：多端点意味着标签来自多个模型（跨供应商混合）；
   自一致性投票与专家分一致性（0.897）验证了跨模型标签质量稳定。
